RGB 是工业界常用的加色模型：红（R）、绿（G）、蓝（B）三通道各用 0–255 的强度叠加出颜色。写作前端样式或写 OpenCV 实验时，记一批「基色」能省事。

## 常见颜色（RGB）

| 颜色 | R | G | B | HEX |
|------|--:|--:|--:|-----|
| 黑 | 0 | 0 | 0 | `#000000` |
| 白 | 255 | 255 | 255 | `#FFFFFF` |
| 红 | 255 | 0 | 0 | `#FF0000` |
| 绿 | 0 | 255 | 0 | `#00FF00` |
| 蓝 | 0 | 0 | 255 | `#0000FF` |
| 黄 | 255 | 255 | 0 | `#FFFF00` |
| 青 | 0 | 255 | 255 | `#00FFFF` |
| 品红 | 255 | 0 | 255 | `#FF00FF` |
| 灰 | 128 | 128 | 128 | `#808080` |
| 银 | 192 | 192 | 192 | `#C0C0C0` |
| 栗色 | 128 | 0 | 0 | `#800000` |
| 橄榄 | 128 | 128 | 0 | `#808000` |
| 深绿 | 0 | 128 | 0 | `#008000` |
| 紫 | 128 | 0 | 128 | `#800080` |
| 深蓝（navy 近似） | 0 | 0 | 128 | `#000080` |
| 鸭绿/茶色系近似 | 0 | 128 | 128 | `#008080` |

旧文把「深蓝色」和「鸭绿色」都写成 `(0,128,128)`，那是 **teal（蓝绿）** 的值；真正 navy 更接近 `(0,0,128)`。上表已分开。

## 和其它表示

- **HEX**：Web CSS `#RRGGBB`  
- **归一化**：机器学习里常用 0–1 浮点  
- **OpenCV**：默认 **BGR** 顺序，`(255,0,0)` 在 OpenCV 里是蓝不是红  

```python
import cv2
import numpy as np
img = np.zeros((100,100,3), dtype=np.uint8)
img[:] = (0, 0, 255)  # BGR：红色
```

## 使用建议

1. UI 不要只靠纯 `#00FF00` 这种刺眼基色，设计系统会定义主色板。  
2. 打印场景 RGB 与 CMYK 不等价。  
3. 色盲友好：不要只靠红/绿编码信息。  

## 小结

RGB 三元组是跨前端与视觉算法的「普通话」。记住基色、分清 BGR、会换算 HEX，就够应付大多数笔记级需求。


## 在 CSS 与 Canvas 中的写法

```css
color: rgb(255, 0, 0);
color: #ff0000;
```

```javascript
ctx.fillStyle = 'rgb(0, 128, 128)';
```

## 无障碍提示

仅靠红/绿区分状态对色弱用户不友好。图表请叠加形状、线型或文字标签，而不要只换 RGB。

基色表适合当调色板起点；产品界面请落到设计系统 token（primary/secondary），避免满屏纯 `#00FF00`。
